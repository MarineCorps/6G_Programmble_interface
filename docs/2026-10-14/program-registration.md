# 프로그램 등록 기재사항

> **프로그램명(가칭)** 단말 제어패킷 기반 5G 기지국 스케줄링 가중치 조정 프로그램
> **작성일** 2026-10-14
> **대상** OAI-gNB `feature/jbpf-mac-scheduler-hooks` + JBPF 코드렛 + UE 측 demand6 라이브러리

---

## 1. 적용분야

5G/6G 이동통신 기지국(RAN)의 무선 자원 스케줄링 분야.

구체적으로는 ▲기지국 MAC 계층 스케줄러의 QoS 제어 ▲응용 프로그램이 네트워크에
요구사항을 직접 전달하는 애플리케이션–RAN 인터페이스 ▲기지국 런타임 관측 및
정책 주입(in-network programmability) ▲LLM 추론·물리 AI·자율주행 등 상향링크가
버스티하고 지연에 민감한 신규 워크로드를 위한 RAN 최적화 연구에 적용된다.

---

## 2. 본 프로그램의 특징

본 프로그램은 5G 기지국이 단말의 제어패킷을 직접 해석하여 무선 자원 스케줄링
가중치를 실시간으로 조정한다. 기존 기지국은 단말의 버퍼 상태 보고와 QoS 등급만을
근거로 자원을 분배하므로 응용 프로그램이 "앞으로 어떤 성격의 트래픽을 보낼
것인지"를 표현할 수단이 없었다. 본 프로그램은 단말 응용이 16바이트 제어패킷에
트래픽 유형, 예상 전송량, 마감시간을 담아 보내면 기지국이 이를 포착해 해당 단말의
자원 배분 우선순위를 즉시 변경한다.

가장 큰 특징은 기지국을 재컴파일하거나 재시작하지 않고 정책을 교체할 수 있다는
점이다. 제어패킷 해석과 정책 결정 논리는 유저스페이스 eBPF 코드렛으로 분리되어
기지국 동작 중에 소켓을 통해 적재·해제된다. 코드렛은 적재 전 정적 검증기를
통과해야 하므로 무한 루프나 메모리 경계 위반이 원천적으로 불가능하고, 기지국
프로세스 내부에서 호출 스레드에 인라인 실행되어 패킷 복사가 없다.

제어패킷은 별도 제어 평면이 아니라 일반 사용자 트래픽과 같은 경로로 전송된다.
기지국이 코어망으로 전달하기 전 복호화 직후 지점에서 포착하므로 수신 서버를
운용할 필요가 없다. 정책 적용 경로는 비동기 큐와 읽기-쓰기 잠금으로 실시간
스케줄러 스레드와 분리되어, 코드렛의 처리 지연이 무선 프레임 타이밍으로
전파되지 않는다.

다중 단말 환경을 전제로 설계되었다. 가중치는 단말 간 자원 배분 순서를 결정하므로
경합 단말이 둘 이상일 때 의미를 가지며, 단말별 상태를 독립 관리하고 접속이 종료된
단말의 정책을 자동 회수하여 식별자 재사용 시 이전 정책이 잘못 승계되는 것을
방지한다.

## 3. 주요기능

**(1) 단말 제어패킷 생성·전송** — 단말 측 라이브러리가 응용의 데이터 전송을 감지해
제어패킷을 함께 발신한다. 표준 소켓 함수(send, sendto, write)를 가로채므로 응용
소스를 수정하지 않고 환경변수 설정만으로 동작한다. 제어패킷에는 프로토콜 식별자,
트래픽 유형, 흐름 식별자, 예상 전송량, 마감시간이 담긴다. 단발·주기 반복 전송용
독립 도구도 제공한다.

**(2) 계층별 관측 지점 제공** — 기지국 데이터 경로와 스케줄러 내부에 여섯 개의 관측
지점을 삽입하였다. 상향링크 복호화 직후, 코어망 전달 직전, 하향·상향링크 자원 할당
확정 직후, 버퍼 상태 보고 수신, 자원 요청 감지 지점이다. 적재된 코드렛이 없으면
포인터 한 번만 읽고 반환하여 평상시 부담이 없다.

**(3) 제어패킷 해석·정책 결정** — 코드렛이 프로토콜 버전, 전송 계층, 목적지 포트,
프로토콜 식별자를 차례로 검사해 제어패킷을 선별하며 단계마다 메모리 경계를 확인한다.
선별된 패킷의 트래픽 유형으로 가중치를 결정해 본체에 전달한다. 유형은 대화형 추론,
영상·행동 인식, 실시간 영상, 대용량 전송 네 가지다. 가중치가 바뀌는 순간에만
전달하고 일정 주기마다 재확인해 전달 실패 시 자동 복구된다. 단말별 상태는 독립
관리되며 저장 공간이 부족해도 정책 전달은 멈추지 않는다.

**(4) 가중치 테이블 관리** — 코드렛의 내부 식별자를 무선 구간 식별자로 변환하고
고정소수점을 부동소수점으로 환원해 단말별 테이블에 반영한다. 가중치는 안전 범위로
제한되어 잘못된 코드렛이 스케줄러를 장악하지 못한다. 식별자 선형 탐색 방식이라 서로
다른 단말의 정책이 섞이지 않는다. 기본값 적용은 정책 해제로 해석되며 전체 해제와
접속 종료 단말 자동 회수를 지원한다. 영구 정책은 조회 시 시간 확인을 생략해 매 전송
단위마다 불리는 경로의 비용을 없앴다.

**(5) 스케줄러 가중치 반영** — 하향·상향링크 스케줄러가 단말별 우선순위 점수를
계산하는 지점에서 가중치를 곱한다. 점수 정렬이 자원 할당 순서를 정하므로 가중치가
높은 단말이 먼저 배정받는다. 정책이 없는 단말은 기본값이 적용되어 기존 비례 공정
스케줄링과 동일하게 동작한다.

**(6) 관측·보고 및 생애주기 관리** — 단말별 제어패킷 수신 횟수와 누적 요청량을
주기적으로 보고한다. 자원 요청 신호·버퍼 상태 보고의 패킷 수준 출력, 상향링크 흐름
정보 추출, QoS 흐름별 분류를 별도 코드렛으로 제공한다. 코드렛 생애주기는 단일 명령
도구로 관리한다.

## 4. 사용방법

**(1) 빌드** — eBPF 활성화 옵션과 함께 기지국을 빌드한다. 제공 스크립트에 옵션이
포함되고 관측 프레임워크도 소스 트리에 있어 함께 빌드된다.

**(2) 기지국 실행** — 프로세서 성능 모드를 설정한 뒤 제공 스크립트로 구동한다.
스크립트가 지정하는 프로세서 할당은 무선 프레임 타이밍에 영향을 주므로 변경하지
않는다. 초기화 성공 메시지와 관리 소켓 경로를 확인한다.

**(3) 코드렛 적재** — 동작 중인 기지국에 관리 도구로 적재한다. 상태 조회로 적재
가능 목록을 먼저 확인할 수 있고, 적재 명령이 소스를 자동 재빌드한다. 수정 후에는
재적재 명령 하나로 해제·빌드·적재가 수행되며 기지국 재시작이 필요 없다.

**(4) 제어패킷 전송** — 단말에서 목적지 주소와 트래픽 유형을 지정해 전송한다.
마감시간·예상 전송량 지정과 주기 반복이 가능하다. 기본값 유형은 해당 단말,
전체 해제 유형은 전 단말의 정책을 해제한다. 응용 트래픽에 자동 동반시키려면 단말
라이브러리를 미리 적재하고 환경변수로 설정한다. 목적지로 향하는 경로는 반드시 5G
데이터 세션을 경유해야 하며, 수신 서버는 필요 없다.

**(5) 동작 확인** — 기지국 출력의 정책 반영 기록에서 단말 식별자와 적용 가중치를
확인한다. 가중치는 단말 간 배분 순서를 조정하므로 경합 단말이 둘 이상이어야 효과가
나타난다. 두 단말에 동시 부하를 주고 한쪽에만 정책을 적용해 점유 비율 변화를 측정한다.

**(6) 종료·검증** — 해제 명령으로 코드렛을 내린다. 가중치 테이블은 기지국 재시작
시 초기화된다. 회귀 시험이 기지국 없이 단독 수행되어 식별자 충돌 격리, 정책 해제,
단말 회수, 만료 등 열네 개 항목을 검사한다.

## 5. 본 프로그램을 구동시키기 위하여 다른 프로그램이 필요한지의 여부

**필요하다.** 본 프로그램은 5G 기지국 소프트웨어의 확장 형태로 동작하므로 아래
구성요소가 함께 요구된다.

### 5.1 필수 소프트웨어

| 구분 | 구성요소 | 라이선스 | 역할 |
|---|---|---|---|
| 기지국 본체 | OpenAirInterface 5G (openairinterface5g) | OAI Public License V1.1 | 본 프로그램이 확장하는 대상 기지국 |
| 관측 프레임워크 | jbpf (Microsoft Project Janus) | MIT | 유저스페이스 eBPF 적재·실행·검증 |
| 무선장치 구동 | USRP Hardware Driver (UHD) | GPL-3.0 | 무선 송수신 장치 제어 |
| 5G 코어망 | 5G Core (예: OAI 5GC, Open5GS) | 각 프로젝트 기준 | 단말 등록 및 데이터 세션 설정 |
| 컴파일러 | GCC, CMake, Ninja | GPL / BSD | 기지국 빌드 |
| eBPF 컴파일러 | Clang 14, LLVM 14 | Apache-2.0 | 코드렛 빌드 |
| 운영체제 | Linux (Ubuntu 24.04 기준) | GPL-2.0 | 실행 환경 |
| 스크립트 실행 | Bash, Python 3 | GPL / PSF | 관리 도구 및 제어패킷 전송 도구 |

관측 프레임워크가 내부적으로 사용하는 구성요소는 소스 트리에 함께 포함되어 있다.
Concurrency Kit(BSD-2-Clause), mimalloc(MIT), uBPF(Apache-2.0),
eBPF verifier(MIT)이며 모두 별도 내려받기 없이 함께 빌드된다.

### 5.2 필수 하드웨어

소프트웨어 정의 라디오 장치가 필요하다. 개발 환경은 USRP X410을 10기가비트
이더넷으로 연결하여 사용하였다. 단말 측은 5G 통신 모듈을 탑재한 장치 또는 5G
모뎀이 연결된 컴퓨터가 필요하며, 제어패킷 전송 도구를 실행할 수 있어야 한다.

### 5.3 선택 사항

기지국 성능 분석 시 Linux perf 및 FlameGraph(CDDL/GPL)를 사용할 수 있다. 시험용
가입자 식별 모듈 발급에는 pySim(GPL-2.0)을 사용할 수 있다. 외부 제어 평면 연동
시에는 FlexRIC(Mozilla Public License 2.0)을 함께 빌드할 수 있다. 세 항목 모두
본 프로그램의 동작에 필수적이지 않다.

### 5.4 라이선스 정합성

본 프로그램이 직접 포함하거나 수정한 구성요소는 모두 허용적 라이선스(MIT,
BSD-2-Clause, Apache-2.0)이며, 기지국 본체의 OAI Public License V1.1(Apache-2.0
파생)과 호환된다. 각 구성요소의 라이선스 원문과 저작권 표시는 소스 트리에 그대로
보존되어 있다. 무선장치 구동 소프트웨어는 별도 프로세스가 아닌 라이브러리로
연결되므로 배포 시 해당 라이선스 조건을 확인해야 한다.
